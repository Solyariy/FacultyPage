# Програми обміну — відповіді

Розділ винесено в окремий застосунок `exchange`, тож уся його історія міграцій
проходиться командами `python manage.py migrate exchange zero` / `python manage.py migrate`
і не зачіпає решту сайту.

| Міграція | Що робить |
|---|---|
| `0001_initial` | Модель `ExchangeProgram`: id, університет, мови, кількість місць (текст), дедлайн (дата), опис |
| `0002_seed_programs` | `RunSQL`: таблиця деканату як є + описи |
| `0003_exchangeprogram_country` | Нове поле «країна» |
| `0004_split_university_country` | `RunPython`: розділяє «університет» на назву і країну |
| `0005_exchangeprogram_seats_count` | Тимчасове числове поле `seats_count` |
| `0006_convert_seats` | `RunPython`: текст → число |
| `0007_seats_integer` | Видаляє текстове поле, перейменовує `seats_count` → `seats` |

## 3. Що робити зі значенням «до 4»?

Зберігаємо **4**. "до 4" нічим принципово не відрізняється від "5" чи "2 місця".

## 4. Чи варто зберігати статус прийому окремим полем у базі?

**Ні.** Легше парсити по `deadline`.

## 5. Міграції, що відкочуються з втратою даних

Усі міграції зворотні, і `migrate exchange zero` → `migrate`.

| Міграція | Що втрачається при відкаті |
|---|---|
| `0001_initial` | Таблиця видаляється: **усі** програми, зокрема додані або змінені через адмінку. Після повторного `migrate` повернуться лише 6 програм із таблиці деканату. |
| `0002_seed_programs` | Видаляються 6 програм деканату разом із будь-якими правками до них з адмінки. Програми, додані вручну, залишаються. Видалення йде за префіксом назви (`LIKE 'KU Leuven%'`), бо після відкату `0004` формат рядка вже інший (див. нижче). |
| `0004_split_university_country` | Назва й країна зливаються назад, але **оригінальний роздільник втрачено**: `KU Leuven (Бельгія)` і `University of Tartu - Естонія` повертаються як `KU Leuven, Бельгія` і `University of Tartu, Естонія`. |
| `0006_convert_seats` (+ `0007_seats_integer`) | Текстова кількість місць відновлюється лише як число: `2 місця` → `2`, `до 4` → `4`, `1 місце` → `1`. Слова і позначка «до» втрачаються. |

Без втрат відкочуються `0003` і `0005`: їхні поля на момент відкату вже або злиті
назад (`country` після відкату `0004`), або не потрібні (`seats_count` після відкату
`0006`). `0007` сам по собі нічого не втрачає: тимчасовий `default=""` лише дозволяє
знову додати NOT NULL текстову колонку в таблицю з рядками, а значення в неї записує
відкат `0006`.
